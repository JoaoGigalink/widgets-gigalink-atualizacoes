# Atualização `2026-07-22.1` — Esteira vs Churn, Vendas mensal, fix de sessão expirada

Instruções pra aplicar no `widget.html` (e em alguns casos `main.js`/
`preload.js`) **local** — a cópia que já roda nesta máquina, com suas
próprias customizações (botão de pausa, gráfico, timing, etc). **Não
sobrescrever nenhum arquivo inteiro por cima** — cada seção abaixo
descreve a intenção da mudança e o formato de dado antes/depois, pra
você localizar o trecho equivalente no código local e editar só isso.

Depois de aplicar tudo, atualizar a constante `APP_VERSION` no topo do
`widget.html` local pra `"2026-07-22.1"` — isso apaga o indicador de
atualização pendente que aparece no widget.

---

## 1 — URL do endpoint (Esteira vs Churn)

Encontre a chamada `fetch(...)` que bate em
`` `${BASE_URL}/widget/ativacoes-churn-semanal` ``. Trocar por
`` `${BASE_URL}/widget/esteira-churn-semanal` ``.

## 2 — Formato da resposta da API mudou (Esteira vs Churn)

Antes (`ativacoes-churn-semanal`), cada item do array era:
```json
{ "semana": 30, "ativacoes": 42, "churn": 1200.50, "churn_pct": 3.1, "ultima_data": "20/07/2026" }
```

Agora (`esteira-churn-semanal`), cada item é:
```json
{ "semana": 30, "esteira_ativacao": 85000.00, "variacao_esteira": -4.2, "churn": 9300.00, "churn_pct": 10.9, "ultima_data": "20/07/2026" }
```

O campo `ativacoes` (contagem, somada por semana) deixou de existir —
virou `esteira_ativacao` (valor em R$, **não é soma**, é o saldo do
último dia daquela semana). Tem também um campo novo, `variacao_esteira`
(variação % da semana, pode vir `null`).

**`churn` mudou de significado**: antes era o churn *daquela* semana;
agora já vem **acumulado** — a API soma tudo desde a primeira semana do
array até a semana atual antes de responder, então o valor de cada
semana é sempre maior ou igual ao da semana anterior (nunca cai).
`churn_pct` é calculado em cima desse valor já acumulado. Isso é
transparente pro front — o campo continua se chamando `churn`, só o
número que vem nele é diferente.

## 3 — Onde essa mudança de campo se propaga

No código local, ache toda referência a `.ativacoes` vinda dessa
resposta (ex.: `d.ativacoes`, `item.ativacoes`, dentro da função que
desenha o gráfico desse slide e monta os textos) e troque por
`.esteira_ativacao`. Isso vale mesmo que a função de desenho do gráfico
tenha sido customizada — o dado de entrada muda, a lógica de desenho
(barras, cores, animação, pausa) pode continuar exatamente como está.

Exibir `variacao_esteira` em algum lugar (ex.: ao lado do valor, como já
faz com `churn_pct`) é opcional — o slide funciona sem isso.

## 4 — Textos visíveis (Esteira vs Churn)

Qualquer texto fixo na tela que diga "Ativações" (título do slide,
legenda, tooltip, label de estatística) deve virar "Esteira". Além
disso, todo texto fixo que diga só "Churn" deve virar "Churn
(acumulado)" ou "churn acumulado", pra deixar claro que não é mais o
valor da semana isolada. Não mexer em outros textos.

## 5 — Cor/legenda (opcional, cosmético)

Se houver uma variável de cor tipo `--ativacoes` no CSS usada só pra essa
série do gráfico, pode manter o nome ou renomear pra `--esteira` — é só
estética, não quebra nada se ficar como está.

## 6 — Vendas por vendedor: dia → mês

Encontre a chamada `fetch` que bate no endpoint de vendas do vendedor
(`widget/vendas-por-vendedor` — mesmo endpoint de antes, só o formato da
resposta muda pra quem loga como vendedor).

Antes, a resposta era:
```json
{ "meu_valor": 3200.00, "melhor_dia": 4100.00, "media_vendedores": 2650.00 }
```

Agora:
```json
{ "meu_valor": 41000.00, "melhor_mes": 58000.00, "media_mes": 36500.00 }
```

No código local, ache onde lê `.melhor_dia` e `.media_vendedores` dessa
resposta e troque por `.melhor_mes` e `.media_mes`. `meu_valor` continua
com o mesmo nome (só que agora é o acumulado do mês, não do dia). Se
tiver texto fixo dizendo "Melhor do dia" ou algo do tipo, trocar pra
"Melhor do mês" / "Média do mês". O restante do gráfico (barras, cores,
animação, pausa) continua igual — só o significado do número mudou.

**Nota**: o critério de "o que conta como vendido" também mudou no
backend (agora inclui contratos ainda não instalados e até cancelados
que chegaram a ser ativados antes de cancelar) — isso não muda o formato
da resposta, só faz os números ficarem maiores que antes. Não é bug se
os valores parecerem mais altos do que o habitual.

## 7 — Botão de refresh manual (opcional)

Foi adicionado, na versão canônica, um botão de refresh manual (ícone
↻) perto do botão de trocar senha — chama de novo a mesma função que já
roda a cada 60s. Se quiser esse botão também:
1. Adicionar um `<button>` parecido com o de trocar senha existente.
2. No JS, um listener de `click` que chama a função de recarregar todos
   os slides.
3. Opcional: uma animação curta de giro no clique.

Independente do resto — pode ser aplicado ou ignorado sem afetar mais
nada.

## 8 — Gráfico de Faturamento virou série temporal

Mudança de conteúdo/dado exibido, não estética.

Antes, o gráfico do slide de Faturamento desenhava barras de variação
semanal (`variacao_semana`, divergindo de uma linha zero central).
Agora desenha uma linha suave + área com gradiente do **valor real** do
faturamento (`faturamento`) ao longo das semanas, com escala ajustada ao
range dos dados (não mais a partir de zero) e um ponto maior destacando
a semana atual.

A API (`widget/faturamento-semanal`) não mudou — mesmo formato de
resposta de sempre (`semana`, `faturamento`, `variacao_semana`,
`ultima_data`, mais um campo novo `versao_atual`/`changelog` usado só
pro indicador de atualização, ver seção 10). Só a função que desenha o
SVG desse slide mudou. Se esse gráfico foi customizado especificamente
(cores, animação, tipo de visualização), a decisão de aplicar essa
mudança ou não é de quem mantém essa cópia — a intenção é essa (linha
temporal do valor, não mais barras de variação), mas pode manter a lógica
de desenho customizada com esse novo enfoque, se preferir.

## 9 — Fix de sessão expirada (401) — recuperação automática

Esse fix toca **3 arquivos diferentes**: `main.js`, `preload.js` e
`widget.html`. Procure com cuidado se algo em `main.js` foi customizado
antes de aplicar por cima.

**Problema que isso resolve**: hoje, se a chave (`widgetKey`) salva
localmente for invalidada por qualquer motivo (troca de senha em outra
máquina/sessão, revogação manual, etc.), o app mostra "Erro: HTTP 401"
pra sempre em cada slide, sem nenhuma recuperação — precisa fechar e
reabrir manualmente.

**Em `main.js`:**
1. Adicionar uma função `clearSession()` que apaga o arquivo de sessão
   local.
2. Adicionar uma função `handleSessionExpired()` que: chama
   `clearSession()`, fecha todas as janelas de widget abertas, zera a
   flag de "widgets já iniciados", fecha a janela de trocar senha se
   estiver aberta, e abre a janela de login (se não houver uma já
   aberta).
3. Registrar um handler IPC novo, `sessao-expirada`, que só chama
   `handleSessionExpired()` e devolve `{ ok: true }`.
4. Se as janelas de widget já são guardadas numa lista/array (pra
   permitir fechá-las depois), reusar essa lista. Se não, adicionar isso.

**Em `preload.js`**: expor mais um método em `window.widgetAPI`:
`sessaoExpirada: () => ipcRenderer.invoke("sessao-expirada")`.

**Em `widget.html`**: em cada função que faz `fetch` (Faturamento,
Esteira/Churn, Vendas), depois do `fetch`, checar especificamente
`res.status === 401` **antes** de tratar como erro genérico — se for
401, chamar `window.widgetAPI.sessaoExpirada()` (com uma variável de
guarda tipo `let sessaoExpirando = false`, pra não disparar mais de uma
vez se várias chamadas 401'arem quase juntas).

**Como testar**: com o app fechado, editar manualmente o arquivo de
sessão local pra colocar uma chave inválida, abrir o app — ele deve
detectar o 401 na primeira tentativa de carregar dados e abrir a tela de
login sozinho, sem precisar fechar/reabrir manualmente.

## 10 — Indicador de atualização pendente (novo mecanismo)

A partir desta versão, a resposta de `widget/faturamento-semanal` também
inclui `versao_atual` e `changelog` em cada item do array. Se o
`widget.html` local ainda não tiver isso:

1. Adicionar uma constante no topo do `<script>`: `const APP_VERSION = "2026-07-22.1";`
2. Uma função que compara o último item da resposta de Faturamento
   (`data[data.length - 1].versao_atual`) contra `APP_VERSION` — se
   forem diferentes, mostrar um indicador visual discreto (ex.: uma
   bolinha pequena perto do botão de refresh) com um `title`/tooltip
   mostrando o `changelog`.
3. Chamar essa função depois de carregar os dados de Faturamento.

Esse indicador é só um aviso passivo — não aplica nada sozinho. Serve pra
sinalizar, sem precisar checar manualmente, que existe uma versão mais
nova disponível neste mesmo repositório de atualizações.

## 11 — O que NÃO mexer

Botão de pausa, intervalo de troca de slide (`SLIDE_MS` ou equivalente),
tipo de gráfico/animação do slide de Esteira vs Churn e de Vendas, e
qualquer reskin visual (cores, blur, formato de botões, animações de
paginação) que já exista localmente e não seja mencionado nas seções
acima — nada disso tem relação com esta atualização. Se parecer
necessário tocar em algo fora do escopo das seções 1 a 10 pra fazer
funcionar, é sinal de que algo foi mal entendido — parar e perguntar
antes de prosseguir.

## 12 — Depois de aplicar

Confirmar que:
- o slide do meio mostra "Esteira" no lugar de "Ativações", com valor em R$;
- o slide de Vendas (papel vendedor) mostra "Melhor do mês"/"Média do mês";
- o slide de Faturamento mostra a linha/área da série temporal, não mais
  barras de variação;
- forçando uma chave inválida no arquivo de sessão, o app volta pra tela
  de login sozinho em vez de travar em "Erro: HTTP 401";
- o botão de pausa, o timing e o visual geral continuam se comportando
  como antes (nada fora do escopo foi alterado).

Por fim, **atualizar `APP_VERSION` local pra `"2026-07-22.1"`** — isso
apaga o indicador de atualização pendente.

## Troubleshooting

- **Slide de Esteira mostra "Sem dados."**: confirmar conexão com a API
  de produção — não deveria depender de nada local.
- **Slide mostra "Erro: HTTP 404"** no lugar de Esteira vs Churn: alguma
  cópia antiga do endpoint (`widget/ativacoes-churn-semanal`) ainda está
  sendo chamada em algum lugar do código — revisar a seção 1.
- **Slide de Vendas continua vazio**: não relacionado a esta atualização
  — é uma pendência conhecida do lado do backend (dados históricos ainda
  sendo preenchidos), não um problema do `widget.html`.
- **Valor de "Churn (acumulado)" só cresce, nunca cai**: isso é esperado
  — é uma curva sempre crescente por design (ver seção 2), não reseta
  por mês nem por ano.
